Multi-Client DJ Server

The vision of this project is to be able to network two or three phones at a party to be able to use them as a DJ system.

Background

I have been DJing for a long time and always been curious by technical problems involving audio and the inner workings of DJ gear. For example, around 2015 when the Web Audio API was becoming stable, I made a web page to emulate the control tone of digital-vinyl, complete with a virtual scratchable turntables using the Canvas API. With it, I was able to connect my phone to my live vinyl system via a 3.5mm to RCA cable and emulate a turntable but smartphones then were not so responsive, browsers not so optimized and actual DJ equipment was still needed.

Since then:

  • Smartphones have become more powerful and browsers more optimised.
  • I have been doing professional backend development in Rust for some years, including with WebSockets.
  • Vibe coding has come into existence.

So, I arrived at new vision. Could I show up to a party with a couple of USB-C audio adapter cables and a phone and be able to DJ with a friend without DJ hardware? From my experience the bare minimum for a DJ system is as follows:

  • Two decks.
  • A crossfader
  • A master output for the speakers
  • A headphone output for the DJ to preview the mix
  • Tempo control/pitch faders for beatmatching
If I could figure out a way to sync playback across two devices, I could split the master and headphone outputs across two phones and have the Web Audio API handle the fading and pitch control... I started to research how first-person shooter games sync their state and player actions so smoothly and drew inspiration from that to guide the vibe coding.

Borrowing From Game Netcode

The server is the sole authority on every deck's state — clients only ever send requests, never assert outcomes. But past that, I ended up leaning on a handful of tricks from multiplayer game networking, applied to a mixer instead of a shooter:

  • A press of Play doesn't take effect the instant the server gets it — the server picks an instant 150ms in the future and broadcasts that, giving every client's network enough slack to receive and arm it. Same shape as a race game broadcasting a start time instead of a start signal.
  • Every deck carries a monotonically increasing revision number, so a client can silently drop anything stale or duplicated — the same job a sequence number does in UDP-based game netcode.
  • Dragging the tempo fader applies to your own screen immediately, client-side-prediction style, while everyone else watches it ~90ms behind the live edge, interpolating between the two samples straddling that delayed instant — the "render the past, smoothly" trick that makes other players' movement look continuous on a discrete update rate.

Underneath all of it sit three separate clocks that don't agree with each other by default: the server's own monotonic clock, each browser's performance.now(), and the Web Audio hardware clock that actually decides when a speaker makes a sound. Each browser estimates its offset from the server with an NTP-style round trip — burst of eight, keep whichever sample had the lowest travel time — and separately learns its own fixed audio-output bias with a silent calibration probe, because it turns out browsers can be quietly, consistently wrong about their own latency by half a second.

What's Actually On The Decks

Each of the two decks gets a waveform with click-to-seek, a DJ-style cue point (hold to preview, release to snap back), a 16-beat loop with adjustable re-loop, tempo with pitch-lock, a bass-cut kill switch, and background BPM detection. A room-wide crossfader blends the two decks into the master mix, with its own slider for the blend curve — smooth equal-power at one end, a hard plateau cut at the other — visualised live on a canvas so you can see the curve you've configured.

The headphone/master split is the feature the whole thing was built for: a client can register as a headphone source and it'll only ever play decks with "pre-fader listen" enabled, muted from everything else — genuinely pre-fader, so it's unaffected by wherever the crossfader currently sits, exactly like the real thing.

Try It Out

Live at dj.bakun.in -- open it on two devices (or two tabs) to actually see the sync in action; on its own it just looks like a regular DJ app. Currently, you'll need to have the same audio files available to both devices for the full experience.
